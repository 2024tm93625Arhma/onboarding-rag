# Service Desk KT Session - Software Requests

Transcript of a knowledge transfer session recorded for new Service Desk
analysts. Lightly edited for readability.

**Presenter:** Today we are going through software requests, because they are
about a fifth of our tickets. First thing: always check whether the software
is already in the self-service catalogue. If it is, point the user there and
close the ticket. They do not need approval for catalogue items.

**Attendee:** And if it is not in the catalogue?

**Presenter:** Then it has to come in as a software request on the service
portal. Make sure the request has the software name, the version, the
business reason and whether a paid licence is needed. If any of that is
missing, send it back to the user before it goes to their manager.

**Attendee:** Who approves it?

**Presenter:** The user's manager. If IT Security has never assessed the
software, it also goes to them for review. You will see the *Security
review* flag on the ticket.

**Attendee:** What do we tell users about timing? That is what they always
ask.

**Presenter:** Once it is approved, we install it or add it to the
catalogue within 5 business days. If a new paid licence is needed and
procurement gets involved, it can take longer, and the user is given an
expected date when the request is approved.

**Attendee:** What if someone asks for something on the prohibited list?

**Presenter:** Reject it and quote the policy. Peer-to-peer tools, cracked
software, personal VPNs and unapproved remote-access tools are never
allowed, however senior the person asking is.

**Attendee:** Browser extensions?

**Presenter:** Same rules as any other software. Only extensions on the
approved list.

**Presenter:** That is it for software. Next session covers access requests.
